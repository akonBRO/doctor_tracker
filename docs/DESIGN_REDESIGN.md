# Stage 3 design brief

The Stage 2 screenshots were reviewed before editing. The split promotional auth screen, decorative landing diagram, forest palette, tiny labels and repetitive reassurance copy obscure the actual records work. Before images are preserved in `docs/screenshots/before/`.

Two directions were considered: an editorial registry with oversized serif titles and warm paper; and a clinical ledger with compact graphite navigation, strong sans-serif hierarchy, open tables and task-focused forms. The clinical ledger is selected: it supports long conditions, international names and repeated administrative tasks more directly.

The brief is an administrative registry for desktop through 320px phones. Use mineral white `#f5f5f2`, white surfaces, graphite `#22272b`, secondary ink `#596168`, rules `#d7d9d6`, rust `#863e30` for primary actions, and separate semantic error/success colors. Body and inputs are 16px, tables 15px, supporting labels 14px, section titles 22px, page titles 36px. Self-hosted DM Sans provides body text and Manrope provides headings. No gradients, invented metrics, decorative avatars or placeholder patient rows.

The landing becomes a typographic introduction with Log in as the primary action and two real capabilities. Authentication becomes one task-focused column. The shell uses a dark navigation rail, identity and logout; content uses aligned rules and open sections. Tables become labeled records on narrow screens. Forms use explicit labels, visible focus and inline errors. The logo symbol paths and wordmark structure stay unchanged; colors follow the new palette, including the favicon and inverse assets.

References inspected: [OpenDesign catalog](https://open-design.ai/skills/), [Design Brief](https://open-design.ai/plugins/example-design-brief/), [Design refine](https://open-design.ai/plugins/od-design-refine/). The brief's explicit palette, density and constraints and Refine's critique/patch/review loop inform this local implementation. These plugins are reference material, not installed runtime dependencies. [Export to Next.js](https://open-design.ai/plugins/od-nextjs-export/) was also inspected for App Router handoff context; the existing Next App Router and separate Express API are retained.

Stage 4 analytics remain reserved. The final visual verification record follows the evidence matrix.

Review changes made from actual rendered screenshots: removed a redundant three-label hero strip, added breathing room below the mobile hero actions, aligned doctor lookup controls with the other filters, and kept the smallest labels at 13px. The mobile navigation now contains keyboard focus while open, closes on Escape and restores focus to its trigger. Patient saves provide explicit confirmation and doctor-scoped creation opens the first patient page.

Visual review completed across 1440, 1024, 768, 375 and 320px for all page types in the matrix. Both production and development suites pass 10 browser tests. The review checked hierarchy, readable type, aligned controls, long record layouts, primary actions, logo consistency and overflow. No unintended horizontal scrolling or axe WCAG A/AA rule violations were found on checked views. The final 60 captures come from production, with no development toolbar. At 320px, the doctor save action keeps one line by omitting its decorative arrow. Chromium and automated axe scans do not replace testing on physical devices or a comprehensive assistive-technology audit.
